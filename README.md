# Ozon Ads Manager

Веб-приложение для автоматизации управления рекламными кампаниями на Ozon
через **Performance API**. Позволяет подключать API-ключи, просматривать
статистику, управлять кампаниями (вкл/выкл, бюджеты, ставки) и автоматизировать
рутину: автоотключение по бюджету, расписания работы, динамические ставки.

## Возможности

- **Подключение ключей** — Client-Id / Client-Secret шифруются (Fernet) и
  проверяются тестовым запросом при добавлении.
- **Кампании** — список с фильтрами по статусу/типу, карточка кампании,
  запуск/остановка, изменение дневного и общего бюджета.
- **Статистика** — сбор по дням, графики (Chart.js), экспорт в CSV,
  детальный отчёт по товарам.
- **Ставки** — изменение ставок отдельных товаров и массовое (на %, на сумму,
  фиксированное значение).
- **Авто-правила** — уведомление/остановка при достижении порога бюджета;
  авто-ставки по метрикам (CTR, конверсия, CPA) с ограничениями min/max.
- **Бидер (управление ставками)** — три стратегии автоматического подбора
  рекламных ставок:
  - *Целевая ДРР от оборота* — ставка подбирается так, чтобы рекламный расход
    не превышал заданный % от всего оборота артикула (реклама + органика);
  - *Поддержание позиции* — через конкурентные ставки API держим свою ставку
    на уровне топ-3/топ-10 при минимальном расходе;
  - *ИИ-подбор* — итеративный тест: шагами повышаем ставку, анализируем CTR
    и ДРР за период, находим оптимум (как «человек-аналитик»).
- **Товары и экономика** — таб «Товары»: маржа с учётом себестоимости,
  комиссии, логистики, эквайринга и % выкупа; остатки, цены, участие в акциях
  и рекламе; ДРР от всего оборота; лимит рекламы на 1 продажу при минимальной
  марже; отметки товаров с малой посещаемостью.
- **Расписания** — кампания сама стартует/останавливается в заданные дни
  недели и часы (часовой пояс настраивается).
- **Журнал** — действия пользователя и авто-правил, логи запросов к Ozon API.
- **Уведомления** — в интерфейсе о важных событиях.
- **Многопользовательность** — регистрация, вход по подписанным cookie.

## Стек

Python 3.11 · FastAPI · SQLAlchemy 2.0 (async) · SQLite/PostgreSQL ·
Jinja2 + Bootstrap 5 + Chart.js · APScheduler · httpx · cryptography.

## Быстрый старт (локально)

```bash
# 1. Установить зависимости
pip install -r requirements.txt

# 2. Создать .env из примера (или оставить значения по умолчанию)
cp .env.example .env

# 3. Запустить
python run.py
```

Откройте http://127.0.0.1:8000 — зарегистрируйтесь и добавьте ключи
Performance API в разделе «Настройки».

## Переменные окружения (`.env`)

| Переменная | Описание | По умолчанию |
|---|---|---|
| `SECRET_KEY` | Ключ подписи сессий и flash-сообщений | `dev-secret-key-change-me` |
| `ENCRYPTION_KEY` | Fernet-ключ шифрования API-ключей. Если пуст — генерируется и сохраняется в `.encryption_key` | пусто |
| `DEBUG` | Режим отладки (reload сервера) | `true` |
| `DATABASE_URL` | SQLite или `postgresql+asyncpg://user:pass@host/db` | `sqlite+aiosqlite:///./ozon_ads.db` |
| `MAX_CAMPAIGNS` | Лимит синхронизируемых кампаний | `100` |
| `SCHEDULER_INTERVAL_MINUTES` | Интервал планировщика (мин., минимум 5) | `5` |

## Docker

```bash
docker compose up -d --build
```

Приложение станет доступно на http://127.0.0.1:8000. Для продакшена
раскомментируйте сервис `db` (PostgreSQL) в `docker-compose.yml` и укажите
`DATABASE_URL` на него.

## Структура проекта

```
app/
├── main.py              # FastAPI, middleware, запуск планировщика
├── config.py            # настройки из .env
├── database.py          # движок и сессии SQLAlchemy
├── models.py            # ORM-модели
├── security.py          # пароли (PBKDF2), шифрование (Fernet), сессии
├── jobs.py              # APScheduler: синхронизация, правила, расписания
├── routers/
│   ├── pages.py         # HTML-страницы
│   └── api.py           # JSON API для AJAX-действий
├── services/
│   ├── ozon_client.py   # клиент Performance API (ретраи, пагинация)
│   ├── campaigns.py     # синхронизация кампаний
│   ├── statistics.py    # сбор и агрегация статистики
│   ├── products.py      # товары и ставки
│   ├── rules_engine.py  # движок авто-правил
│   ├── schedule_service.py # расписания работы кампаний
│   └── logger.py        # журнал действий и запросов API
├── templates/           # Jinja2-шаблоны
└── static/              # CSS/JS
```


Покрыты: шифрование/пароли, нормализация ответов Ozon, клиент Ozon на
mock-транспорте (ретраи, пагинация, ошибки), чистая логика движка правил.

## Примечания по Ozon Performance API

- Базовый хост: `https://api-performance.ozon.ru`.
- Авторизация: заголовки `Client-Id` и `Api-Key`; Api-Key получается из
  Client-Secret через token-эндпоинт и кэшируется.
- Пути эндпоинтов централизованы в `app/services/ozon_client.py` — при
  изменении документации Ozon достаточно поправить их в одном месте.
- Учтите лимиты API: планировщик по умолчанию не чаще 5 минут, клиент
  делает ретраи с экспоненциальной задержкой при 429/5xx.

## Деплой на VDS

1. Установите Docker и `docker compose`.
2. Скопируйте проект, задайте `SECRET_KEY` и `ENCRYPTION_KEY` в `.env`.
3. `docker compose up -d --build`.
4. (Рекомендуется) вынесите `DATABASE_URL` на PostgreSQL и настройте
   reverse-proxy (Caddy/nginx) для HTTPS.
